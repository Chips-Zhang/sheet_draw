# 单音扒谱准确率

从项目根目录运行。音阶与旋律按固定乐谱生成，7 段真实口琴采样随库提供。增加 `--basic-pitch` 可对比 Spotify Basic Pitch 0.4.0 的原始 ONNX 输出。JSON 包含每个音的参考值、预测值及分组统计。

```sh
python -m benchmarks.evaluate --json baseline.json
# 在装有 basic-pitch[onnx]==0.4.0 的单独环境中运行
python -m benchmarks.evaluate --basic-pitch --json baseline-with-model.json
```

| 合成音阶，音高、起止均匹配 | 16 | 1.000 | 1.000 | 1.000 |
| 含休止旋律，音高、起点匹配 | 6 | 0.500 | 1.000 | 1.000 |

| 真实口琴单音，每个文件单独匹配音高 | 7 | 0.600 | 1.000 | 1.000 |

两段合成音阶分别以 22.05、44.1 kHz 生成，每段 8 音，含基频和二、三次谐波。含休止的片段包含跳进和休止前后重复同音。所有引擎使用相同音频，不做分离，关闭乐谱的时值量化，以便测量音符提取本身。旧算法由 `engine="legacy"` 调用，Basic Pitch 使用模型默认阈值。

合成片段的音高按最近的 MIDI 半音（含八度）判定，起点容差为 50 ms，收音容差取 50 ms 和参考时长 20% 中的较大者。每个参考事件最多匹配一个预测事件；汇总各片段的命中数、漏检数和多检数计算微平均 F1。F1 同时扣除漏音与多音。真实录音沿用原文件，包含实际音色和气息，但只有根音标签，故单独评价音高与事件数。开发中查看过这组录音的八度误判并据此改善算法，7/7 属于开发集结果。这个分数不能反映完整演奏中的节奏、连音或压音转录质量。完整乐句的独立评测入口见 `scripts/compare_performances.py`。

实测环境为 Python 3.9、NumPy 1.26.4、SciPy 1.13.1、SoundFile 0.13.1、ONNX Runtime 1.19.2，完整输出见 `results.json`。

## 连续演奏的曲目留出评测

固定上游版本中，`AnnotatedSetupFinalMidi` 含 43 组演奏音频及 MIDI 音高/起止时间人工标注。使用全部 43 组。先前检查过的 Oh! Susanna、Ode to Joy 和 Help Me，以及这些曲目的其他分段，一并划入开发集（3 组曲目，5 段，144 音）。其余 38 段、22 个曲目或练习组划入留出集，共 1,889 个音。每个曲目的不同片段都在同一侧。划分先于本轮评分，没有根据留出结果选择阈值。其中六份导出的 MIDI 文本存在非有限或负的音高、超出录音范围的时间等错误。对 Hey Jude 五段和 Oh! Susanna 第二段，改用同提交 Annotaded 目录中、与评测 WAV 逐字节相同的录音所配的原始 Hz 标注；按各文件列顺序读取起点、终点与频率，再将频率转为最近 MIDI 半音。加载时对整套参考答案检查音高范围和时间边界。两侧录音都来自相同上游数据集，未验证跨录音环境、跨乐手或预训练模型训练集重叠。[音频与人工标注来源](https://github.com/filipemlins/Automatic-Music-Transcription-Harmonica/tree/25bf104035b3aac560324576103dc0c664e87256/AnnotatedSetupFinalMidi) · [冻结清单及 Git blob 指纹](performances_manifest.json)

使用数据集标注的 Richter 口琴调性。除最后一行以外，全部关闭乐谱量化；最后一行使用网页自动节拍网格，保留每个音在网格上的起止位置并反算为秒，跨小节延音只匹配一次。用 mir_eval 一对一匹配音符，音高容差为 50 音分，起音容差为 50 ms。含收音的评分额外要求结束时间偏差在 50 ms 或参考音长的 20% 内，取较宽者。表中为音符微平均。重叠音指与任何其他参考音至少同时发声 30 ms 的音，留出集共有 1,281 个。单行 F1 对照使用完整的复音参考标注，衡量其保留多少演奏信息；这批数据没有另行标注主旋律。

复音输出与官方原始事件逐段同分。双音使用开发集选定的阈值和孔位约束，在留出集上命中 229 个重叠音，单行命中 172 个。双音在量化前，已命中事件的平均起点偏差为 23.8 ms、终点偏差为 83.0 ms，这两个均值不包含漏音。进入用于网页制谱的自动网格后，含收音 F1 从 0.256 变为 0.206。完整数据按片段保存多报、漏报、边界误差，并统计未命中事件中起音仍在容差内的错音与其中相差一个八度的错音。[逐段结果及开发集汇总](performance_results.json) · [开发集阈值对照](neural_profiles.json)

```sh
python -m pip install -e '.[neural]' mir_eval
python scripts/compare_performances.py /tmp/sheet-harp-phrases --json performances.json
```

首次执行约下载 137 MB 的 WAV 和对应文本标注，按固定提交 ID 取文件并核对 Git blob 指纹。可用 `--split dev` 在开发集迭代，用 `--engines monophonic basic-pitch-duet` 指定引擎。合成三连音和切分的分数衡量逐音识别；谱面是否显示三连音、连音线及休止符需以排版测试单独验证。
